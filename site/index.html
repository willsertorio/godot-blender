OVERVIEW GAME GDD ASSETS TRAJECTORY

Overview

This game is a sample: a vertical slice, not a complete game. It was built from the GDD the client shared with us. The same GDD had already been put through other tests: the game was first built in HTML only, then in Unity. This version recreates it with Blender and Godot.

A first version was built directly in Godot from downloaded asset packs. It did not reach the quality bar, especially the guns and hands, so it was set aside and the game was rebuilt Blender first, in the order below.

  1. Keep the gaps the GDD leaves on purpose: no pause, no interaction prompt, the slowdown while aiming never explained.

    2. Learnings

    • The art work pulled the project away from the GDD for a while; the game was then brought back to its loop: a generated dungeon of 8 to 12 rooms, robots, loot, an exit portal and a harder run after each win.

    Tools and sources

    • The client's GDD.
    • Claude Code, working in a cloud container with Godot 4.3 and Blender 4.2.

  2. Concept art

    Create 2D concept art of the game with the help of AI.

    Goal

    • Give Claude an image to work from instead of a description: a concept of the whole scene, the gloved hands, and 24 reference sheets for the environment pieces.
    • A UI concept for the interface: screens and design tokens.

    Learnings

    • Results became consistent once there was a reference to follow; reference images of how a gun is held fixed what written instructions could not.

    Tools and sources

    • AI image generation (Google Gemini for the hand references).
    • Reference images of first-person gun holds.

  3. Modelling in Blender

    Feed the concept art to Claude, which models it in Blender; we review and adjust the models.

    Goal

    • Model every asset from scratch, so the game does not depend on external models.
    • Blender first: nothing went into Godot before a Blender render was approved.

    Learnings

    • Downloaded packs looked too cartoonish and ready-made hands too blocky; modelling from references gave control over the look.
    • The target was realism ("grounded military hardware", then "AAA"); the whole environment set was approved on a single sheet of renders before it went into the game.
    • The hands were the hardest part: the grip, the thumb and the knuckles passing through the gun took many rounds.

    Tools and sources

    • Blender 4.2 LTS, driven by Python scripts, so a change is a re-run rather than a hand edit; Cycles for the review renders.
    • ambientCG PBR textures (CC0): painted plaster, concrete, metal, walkway grating, plastic, rubber, fabric.
    • MakeHuman base mesh (CC0) for the player's arms.

  4. Rigging and animation in Blender

    Rig and animate the models in Blender.

    Goal

    • Each animation described in plain language first (idle sway, fire, reload, inspect), with Claude stating what was feasible before building it.
    • A set of clips for each gun with its hands, and for each robot: idle, shoot, move and death.

    Learnings

    • Motion needs impact: the robots were reworked to be juicier, more exaggerated and more dramatic.
    • Keep it simple: hiding the hands during part of an animation was preferred to fighting the rig.

    Tools and sources

    • Blender armatures: the MakeHuman skeleton and skin weights (CC0) for the arms; joints for the robots' moving parts.
    • Clips baked at 24 fps on one timeline, with a clip table exported alongside each model.

  5. Building the game in Godot

    Once every asset is modelled and animated, bring everything into Godot to build the final game, then test its gameplay and physics.

    Goal

    • A test lab first, one room per robot, to check animations, gunfire and feel before building the full game.
    • Then the GDD's loop: the generated dungeon, a training room, the UI concept and menu music.

    Learnings

    • Feel matters as much as looks: recoil was exaggerated, arcade sounds were replaced by realistic recordings, wrecks give off electrical smoke, footsteps were made quieter.
    • Playing found what tests did not: lights flickering under doors, the frame rate, a spider that seemed to float when shot.

    Tools and sources

    • Godot 4.3 (GL Compatibility renderer, exportable to the web); models brought in as glTF (.glb).
    • Sounds from OpenGameArt (CC0), including The Free Firearm Sound Library; menu music "Exploration Theme" by Cleyton Kauffman (CC0).
    • Barlow fonts (SIL Open Font License).
    • Automated checks and a bot that plays whole runs to measure balance.
